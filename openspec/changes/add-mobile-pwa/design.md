# Design

## Context

- **Narrow windows:** `styles.css` already collapses multi-column layouts at 780px, and turns dialogs into bottom sheets at 520px. `AppShell` has a slide-out sidebar (`mobileOpen`).
- **Mail** already shows the list or the reader on narrow screens, with a back button. That is the pattern for chat and Telegram.
- **`sw.js` exists** (push and click only, no `fetch` handler). Nginx serves `public/` files, and Cloudflare overrides browser cache TTLs.

## Decisions

1. **Breakpoint.** "Phone" means `max-width: 640px`. CSS handles spacing and sizes. Where the structure changes, `useIsPhone()` (a `matchMedia` hook, false in tests unless mocked) chooses what to render, so jsdom tests can cover it.
2. **Manifest.**
   - `public/manifest.webmanifest`: `name` «Atlas — рабочее пространство», `short_name` «Atlas», `start_url` `/?source=pwa`, `scope` `/`, `display` `standalone`, `background_color` `#f5f6f7`, `theme_color` `#176f68`.
   - Icons: 192 and 512 «any», plus 512 «maskable» with padding. `apple-touch-icon.png` is 180px.
   - Icons are generated by a small committed script (`scripts/pwa-icons.mjs`, plain zlib PNG writer), so they can be regenerated.
   - `index.html` links the manifest and adds `apple-mobile-web-app-capable`, `apple-mobile-web-app-title`, `viewport-fit=cover` and `theme-color`.
   - Nginx gets `types { application/manifest+json webmanifest; }` and no long caching for the manifest.
3. **Install.**
   - **«Профиль → Приложение»:** on `beforeinstallprompt` (Chrome on Android and desktop) the event is kept and «Установить приложение» calls `prompt()`.
   - **On iOS Safari** (no such event), a short instruction is shown: «Поделиться → На экран Домой». It also notes that iPhone notifications need this and iOS 16.4 or newer.
   - **Already installed** (`display-mode: standalone`) shows «Приложение установлено».
4. **Offline.**
   - `sw.js` caches `/offline.html`, a self-contained page with inline CSS, on `install`.
   - On `fetch` it handles only top-level navigations: it tries the network and falls back to `/offline.html`. `/api`, `/socket.io` and assets are never intercepted.
   - The page offers «Повторить» (reload).
5. **Phone shell.**
   - The `BottomNav` component sits fixed at the bottom with `env(safe-area-inset-bottom)` padding and 5 items. «Ещё» opens the existing sidebar.
   - Unread badges come from the existing chat and Telegram totals.
   - Pages get bottom padding so the bar covers no content.
6. **Screens.**
   - **`TasksPage`:** on a phone, a `Segmented` with the three categories (remembered per user) renders one column. Moving a task between columns keeps the existing status select on each card.
   - **`MessagesPage` / `TelegramPage`:** with a selection, only the conversation renders, with «Назад»; without one, the list renders. The composer is `position: sticky; bottom: 0`.
   - **`NotificationBell` panel:** `position: fixed` and full width below the top bar on a phone.
   - **`ClientPage`:** phone and email become `tel:`/`mailto:` action buttons at the top; sections stack.
   - **Dialogs:** full-height sheets at 640px and less (today 520px).
7. **Touch basics** (640px and less): controls at least 40px high, `font-size: 16px` on inputs, textareas and selects, and `env(safe-area-inset-*)` padding on the top bar and bottom bar.

## Risks / Trade-offs

- **No visual verification in the workspace.** Tests cover structure (what renders), not pixels. The live check on two phones is the real acceptance. If the workspace image gets the Playwright system libraries, screenshots at 390×844 can be added to the change.
- **The iOS install is manual.** Apple offers no install prompt; the profile explains the two taps.
- **The service worker now handles navigations.** A bug there could break page loads. The fetch handler is limited to `request.mode === 'navigate'`, with network first and the offline page only on failure, and it is unit-tested like the push handlers.
